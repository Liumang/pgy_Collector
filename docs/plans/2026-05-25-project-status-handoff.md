# rednote 项目现状交接

日期：2026-05-25

## 1. 项目目标

当前项目围绕蒲公英博主数据采集，拆成 4 条主线：

1. Mac 桌面采集工具
   - 内置浏览器打开蒲公英找博主
   - 用户在工具内登录蒲公英
   - 右侧面板控制采集、暂停、导出
2. 数据采集能力
   - 当前列表采集
   - 博主昵称上传采集
   - 相似博主采集
   - 常规采集和增强采集
3. 授权与交付
   - 授权码登录
   - 飞书多维表格记录授权状态
   - 授权码生成器单独交付给自己使用
4. 后续数据系统
   - 采集 CSV 进入用户数据库
   - 支持客户、批次、博主、指标、导出记录沉淀
   - 为后续筛选、复盘、推荐和 CRM 做准备

## 2. 已完成

### 2.1 桌面采集工具

- 已从早期 Chrome 插件升级为 Mac Electron 桌面工具
- 工具打开后内置浏览器默认进入蒲公英找博主页面
- 右侧控制栏支持开始采集、暂停、导出、清空、刷新页面
- 当前工具名称为“蒲公英博主采集助手”
- 当前桌面版版本为 `0.1.24`

### 2.2 任务模式

当前支持三种任务模式：

- 当前列表：采集当前筛选结果和后续分页
- 博主昵称上传：读取 Excel 中的昵称，逐个搜索并采集
- 相似博主：读取 Excel 中的昵称，逐个搜索种子博主，点击更多操作里的“寻找相似”，采集推荐列表

多个昵称任务按串行方式执行：一个昵称的搜索、采集、补采完成后，再处理下一个昵称。

### 2.3 采集方式

当前支持两种采集方式：

- 常规采集：采集列表页可见字段，速度较快
- 增强采集：在常规字段基础上，逐个进入博主二级详情页，读取更多详细数据

增强采集采取接近真人的慢速串行方式，不并发打开多个详情页。

### 2.4 导出字段

- 常规采集和增强采集 CSV 表头均已改成中文
- 近 30 日、近 90 日、累计等字段已在表头中明确口径
- 昵称前缀为 `-` 等容易被 Excel 误识别的内容，已做 CSV 安全处理
- 已移除重复字段和不需要的字段，例如旧版 `all_quote`、`source_url`

### 2.5 稳定性处理

- 翻页流程改为一页一个节点：先采当前页，再增强详情，再补采，再翻下一页
- 多页采集不再先全部翻页再回头采详情
- 增强采集详情页增加加载等待和数据缺失补采
- 全部采集完成后会自检空值；如果有空值，只对有空值的博主补采 1 次
- `0.1.24` 增加长时间无进展自动停止保护，避免用户反馈“有时候卡住”后进程一直挂着
- 飞书授权请求增加超时，避免网络异常时授权流程无限等待

### 2.6 授权体系

- 采集助手启动后先进入授权码登录页
- 授权码通过后进入采集界面
- 授权码首次激活后绑定当前机器码
- 同一授权码在其他电脑激活会被拒绝
- 右侧操作栏底部展示客户名和到期日期
- 支持退出登录，回到授权码输入页
- 激活信息写入飞书多维表格，不再使用单独 webhook

### 2.7 授权码生成器

- 已有独立 Mac App：`PGY License Generator.app`
- 只需要填写客户名、授权时长、生成数量
- 生成后自动写入飞书多维表格
- 当前授权码生成器版本为 `1.2.1`
- 生成器包含私钥，只能自己使用，不能发给客户

### 2.8 打包交付

- 采集助手和授权码生成器均使用本地打包脚本生成 `.app` 和 `.zip`
- 打包后会做 ad-hoc codesign
- zip 使用 `ditto -c -k --keepParent` 生成，减少微信或 macOS 解压后提示 App 损坏的概率

## 3. 还没做完

### 3.1 正式签名与公证

当前仍是 ad-hoc 签名，不是 Apple Developer ID 正式签名和 notarization。

影响：

- 部分用户首次打开仍可能需要右键打开
- macOS 安全策略较严时，仍可能出现拦截

后续如果要更正式商业化交付，建议申请 Apple Developer 账号并做正式签名、公证。

### 3.2 用户数据库

当前采集结果主要以 CSV 落地，还没有进入统一数据库。

下一步建议：

- 先做本地 SQLite 或云端 Postgres 的数据模型
- 再做 CSV 导入和采集后自动入库
- 最后做查询、筛选、客户批次和复盘看板

### 3.3 授权安全

当前使用飞书多维表格做单次激活和机器绑定，适合小范围交付。

风险：

- App 内仍包含飞书应用凭证，有被反编译提取的可能
- 真正商业化后，建议迁移到自有服务端，由服务端持有密钥和飞书凭证

### 3.4 采集字段准确性长期维护

蒲公英页面和接口可能改版。后续如果出现字段空值、机构读取错误、合作笔记数量口径变化，需要继续按真实页面样本逐项校准。

## 4. 当前结论

项目已经从“浏览器插件脚本”推进成“可交付的 Mac 桌面工具”：

- 普通用户不需要 terminal
- 可以在工具内完成登录、筛选、采集、导出
- 支持授权码交付
- 支持当前列表、昵称上传、相似博主三种实际业务场景

下一阶段重点不再是单纯采集字段，而是把采集结果沉淀到用户数据库里，形成可复用的数据资产。

## 6. 注意事项

- 不要把授权私钥发给客户
- 不要把 `license-generator/` 当作客户交付包发出
- 不要把飞书 App Secret、私钥、`.pem` 文件写入公开文档
- 用户导出的 CSV 不进入代码仓库或交付包
- 每次交付前必须重新运行检查和打包流程
