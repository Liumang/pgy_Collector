## 2026-05-16 修复增强采集详情 ID 误判

### 背景

用户反馈增强采集逐个打开详情页时，部分博主详情页弹出 `batchGetBaseUserInfoOffline`，页面为空，头像昵称等信息缺失。

### 问题定位

对第一页 20 个博主逐个打开详情页后发现：

- 正常行打开详情页后头像、昵称、数据接口都正常。
- 异常行打开后页面显示小红书号 `--`、粉丝数 `--`、报价为“账号注销”。
- 这些异常行和 CSV 中小红书号、内容标签、相似博主等字段为空的行一致。
- 进一步测试列表真实点击发现，异常行的正确详情 ID 与工具导出的 `blogger_id` 不一致。
- 原因是工具之前会从整行任意 24 位字符串兜底提取 ID，误把头像图片 URL 里的 24 位字符串当成博主详情 ID。

### 本次调整

- 桌面版升级到 `0.1.6`。
- 增强采集的列表阶段强制通过真实点击昵称/博主区域捕获详情 URL。
- 不再信任头像、图片、普通属性里的任意 24 位字符串作为博主详情 ID。
- 常规 ID 提取也收紧为只接受详情链接或明确 `userId`、`kolUserId`、`bloggerId` 等语义字段。

### 验证

对此前失败的 9 个博主测试，真实点击均能捕获正确详情 ID，例如：

- 诗诗崽一枚：错误 ID `64522cf58b966cee8fc5c4ff`，正确详情 ID `58a8742250c4b40b097724da`
- 蜂蜜饼干：错误 ID `62cc07ad5b51e3cae4a61e5f`，正确详情 ID `5fdf46700000000001001ed7`
- 李咔咔：错误 ID `5e72de9b6e90240001c85965`，正确详情 ID `5983dc085e87e76eafbd3236`

## 2026-05-16 桌面版增强采集改为真实详情页捕获

### 背景

用户明确要求空白字段也必须采集，尤其是笔记表现、粉丝增长/活跃、近期笔记等重要字段。

### 问题定位

上一版工具内部直接请求部分详情接口时，这些接口返回 `406`。真实详情页加载时，蒲公英前端会自动生成 `X-s`、`X-t`、`X-S-Common` 等签名请求头；工具直接发普通请求没有这些签名头，因此拿不到数据。

### 本次调整

- 桌面版升级到 `0.1.5`。
- 增强采集改为两段式：
  - 第一段：先采集列表页基础字段，拿到本次需要处理的博主 ID。
  - 第二段：工具逐个打开真实博主详情页，让蒲公英页面自己正常加载签名接口。
- 新增 webview 预加载捕获：
  - 捕获详情页正常返回的 `fans_summary`。
  - 捕获详情页正常返回的 `notes_rate`。
  - 捕获详情页正常返回的 `notes_detail`。
  - 捕获详情页正常返回的粉丝画像、内容标签、相似博主等接口。
- 增强字段从页面真实返回数据里解析，不再用普通 `fetch` 强打会返回 `406` 的接口。
- 采集节奏仍为逐个详情页慢速处理，不并发打开多个详情页。

### 验证

- 使用当前登录态测试单个博主详情页。
- 已确认此前 `406` 的接口在真实详情页加载并捕获时返回 `200`：
  - `fans_summary`
  - `notes_rate`
  - `notes_detail`

## 2026-05-16 桌面版增强字段解析修正

### 背景

用户反馈增强采集导出的 CSV 中很多字段为空，并要求把提示文案从“已触发详情入口，正在慢速读取增强字段”改为“已触发详情入口，正在采集第 x 页的第 y 个博主，慢速读取增强字段中。”

### 问题定位

- CSV 中基础字段、身份字段、内容标签、粉丝省份/兴趣/设备、相似博主等字段已有数据，说明增强采集流程本身在运行。
- 空字段主要集中在笔记表现指标、粉丝增长/活跃、近期笔记详情等字段。
- 真实详情页加载时，蒲公英会给部分接口自动加签名请求头；工具内部普通 `fetch` 直接请求这些接口会返回 `406`，因此这批字段无法直接填充。
- 另有一部分字段属于解析问题：
  - `机构状态` 误读到了 `clickMidNumMcn`。
  - `区县` 没有从 `location` 第三段兜底。
  - `内容细分标签` 没有解析 `taxonomy2Tags`。
  - `女性粉丝占比` 没有解析 `gender.female`。
  - `粉丝最高年龄段` 没有解析 `group`。
  - `粉丝TOP城市` 对 `cities` 字段匹配不准。
  - `近期笔记数量` 在拿不到时被 `Number("")` 误转成 `0`。

### 本次调整

- 桌面版升级到 `0.1.4`。
- 增强采集状态提示改为带页码和序号：
  - `已触发详情入口，正在采集第 x 页的第 y 个博主，慢速读取增强字段中。`
- 修正区县、机构状态、内容细分标签、女性粉丝占比、粉丝年龄段、粉丝城市等字段解析。
- 对拿不到的数据保持空值，不再把空值误写成 `0`。
- 暂停直接请求会返回 `406` 的签名接口，减少无效请求。

用户确认不希望先获取客户机器码再生成授权码，而是由交付方直接按客户名、时长、数量生成授权码；客户激活成功后，再通过 webhook 回传机器码和授权信息。

### 本次调整

- 桌面版升级到 `0.1.22`。
- 授权页不再展示机器码，用户只填写授权码。
- 授权码不再预先绑定机器码。
- 授权成功后通过飞书 webhook 推送：
  - 客户名。
  - 授权码。
  - 机器码。
  - 激活时间。
  - 授权时长。
  - 到期时间。
  - App 版本、公网 IP、系统信息、电脑名。
- 授权码生成器升级到 `1.1.0`：
  - 只填写客户名。
  - 选择授权时长。
  - 填写生成数量。
  - 一次生成多个授权码。

## 2026-05-17 飞书多维表格授权中心

### 本次调整

- 桌面版升级到 `0.1.23`。
- 授权码生成器升级到 `1.2.0`。
- 飞书 webhook 上报取消，改为直接写入飞书多维表格。
- 授权码生成器生成授权码后，会自动写入多维表格授权中心，状态为 `未激活`。
- 采集助手登录时会查询飞书多维表格：
  - 授权码不存在：拒绝登录。
  - 未激活：绑定当前机器码，写入激活时间、最近登录时间、IP、设备信息，允许登录。
  - 已激活且机器码一致：更新最近登录时间，允许登录。
  - 已激活但机器码不同：拒绝登录。
- 授权表和字段会自动检查/创建。

## 2026-05-25 偶发卡住保护

### 背景

用户反馈采集助手有时会卡住，表现为状态长时间不变化。

### 本次调整

- 桌面版升级到 `0.1.24`。
- 授权码生成器升级到 `1.2.1`。
- 飞书授权/写表请求增加 15 秒超时，避免网络异常时界面一直停在生成或登录状态。
- 采集助手增加任务看门狗：
  - 采集中如果超过 8 分钟没有任何状态进展，会自动停止任务。
  - 停止后可以导出已采集数据，或刷新页面后重新开始。
- 手动点击停止后，如果 2 分钟仍未结束，会强制回到可操作状态。
