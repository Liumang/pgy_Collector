# 风险与默认处理

日期：2026-09-13。负责人均为rednote开发；用户不需要操作Terminal。

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 蒲公英“日常笔记”不一定等于所有内容 | 商单比例分母错误 | T02真实页面核对、登记口径；未确认不换一个可用数凑齐 |
| 同名/改名/搜索结果滞后 | 采错人 | ID主身份，关键词绑定，不精确进入候选清单 |
| 主流程和旧内嵌增强两套逻辑 | 修一处另一入口漏改 | T12复用唯一详情执行器，逐步移除已无调用的旧路径，先有入口回归 |
| 状态机调整导致停止/补采回归 | 新旧任务相互影响 | 执行代号贯穿页面回包和保存，暂停/继续/取消分别测试 |
| SQLite与待写队列同时磁盘失败 | 本地无地方持久保存 | 明确显示无法保存，暂停新增工作；不谎报可靠入库 |
| 同步SQLite大导出阻塞采集 | 卡顿/超时 | 固定导出清单和引用，独立只读连接/工作线程按必要引入，避免主服务长事务 |
| 历史时间/零/MCN没有原始证据 | 自动校正会造假 | 保留原值和证据，标记待核对，明确可重刷项 |
| 原始快照去重不当 | 历史丢失 | 先一致性备份/核对，先优化新数据，再处理历史重复副本 |
| 休眠/关机与登录失效 | 定时任务无法执行 | App运行时托管，本地错过合并，恢复先检测；不承诺关机采集 |
| 4万库但网页采集很慢 | 达不到每日2000位 | 分别测数据库性能与采集阶段耗时，不用数据库压测替代网页产能验证 |
| Electron升级影响登录/原生SQLite/DOM | 新版不能打开或采集回归 | 独立检查点、重编译依赖、实测；不混入首批正确性修复 |
| 无Git、旧App众多 | 错版本交付、难回退 | 建立排除敏感文件的源码检查点，固定dist发布入口，不删除用户旧文件 |
| 用户已有采集在运行 | 替换App打断任务 | 发新版前核实运行状态，等安全收尾后关闭旧版打开新版 |
| 本地回环接口缺少公网鉴权 | 不适合远程共享 | 本轮不开放远程入口，云端R10保留挂起；本机边界校验随T25维护 |

范围控制：回收站、诊断备份、逐页节点、任务恢复均用于现有本地数据与可靠性目标；不扩展CRM、投放管理、推荐评分或跨公司共享。默认决定可在实现证据出现后调整，但必须写明原因并更新任务与验收项。
