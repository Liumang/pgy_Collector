# 本地服务优化开发计划

日期：2026-09-13。Plan status：Ready（可据此开始开发，尚未实施）。

## 1. 范围与依据

目标：提高现有Mac本地采集助手的数据准确性、任务恢复能力和大库查询体验。

依据：用户最新指示“先不考虑迁移上云”、当前0.2.3-demo源码，以及`acceptance-work/2026-09-13-cloud-readiness/issue-log.md`的R01-R19。没有独立产品交接包；本计划采用现有审查结果作输入，默认决策见下表。无需补做竞品研究即可执行这些已定位的缺陷修复。

本轮保留Electron、Node/Express、React、SQLite和App内两个Tab。云端PostgreSQL、服务器部署、公司账号/多租户、线上授权与飞书通知均不在本轮范围。R10的公网鉴权问题挂起，不标已解决；本地继续只监听回环地址。

## 2. 执行口径

| 事项 | 本轮决定 |
| --- | --- |
| 昵称上传/相似种子 | 精确可核对匹配才执行；同名多结果或搜索失败进入待确认清单，不自动选第一位 |
| 稳定身份 | 新数据必须有博主ID；两个非空ID不同不得自动合并；昵称与小红书号只作可变资料 |
| 新旧数值 | 旧导入只补历史；普通采集未尝试的增强模块保留上次数据日期；本次增强尝试失败的字段显示-并允许查看上次有效值 |
| 空值 | 无数据、未尝试、失败、有效0分别记录；不拿0填未知 |
| 日常与合作 | 固定近30/90日及业务/笔记类型/流量口径，不跨口径填充；商单比例的分母须先与页面验证 |
| MCN | 未知、明确无机构、有机构分开；只有明确且按时间先后的结果参与变更判断 |
| 自检补采 | 正式采集完成检查一次；仅补有异常缺失的博主一次；明确无数据不反复补采，首次加载的模块重试与结束补采分别计数 |
| 多页增强 | 第二批统一为每页列表节点→该页逐个详情→确认下一页，支持阶段与断点；不直接重新启用旧版另一套增强代码 |
| 日更 | 本机任务清单持久化；暂停、继续剩余、只重试失败；采集仍依赖Mac在线和蒲公英登录 |
| 退出/休眠 | 重开后识别未完成任务并提供继续；错过多个日程默认合为一次待执行，不把多天任务一口气补跑 |
| 删除 | 第三批加入本地回收站；删除标记阻止迟到结果复活，永久删除要显式操作 |
| 交付 | 每批验收后给一个可双击App，放项目dist；记录版本，核实无活动任务后关闭旧版、打开新版；不放桌面 |

上述是实现默认值，不代表已改变产品行为。登录失效或无法验证字段语义时如实标记，不凭猜测补齐。

## 3. 四批交付

| 批次 | 工作包 | 可交付结果 | 出批条件 |
| --- | --- | --- | --- |
| M0 基线 | T00 | 一致性备份、源码检查点、复现基线 | 能恢复测试副本，记录源版本 |
| A 数据准确性（首个可测版本） | T01-T07 | 正确身份、口径、空值、MCN、最新值和入库提示 | AC01-AC07通过；真实代表样本对照；未完成的恢复能力明确列出 |
| B 任务和后台稳定性 | T08-T15 | 后台可恢复、已采结果不丢、暂停续跑、逐页节点、完整任务清单 | AC08-AC15通过；退出重开/丢回执/慢页面故障注入通过 |
| C 查询导出与数据维护 | T16-T22 | 轻量列表、全量导出、搜索修正、详情稳定、回收站与历史核对 | AC16-AC22通过；无200条/8条静默截断 |
| D 容量验证与交付 | T23-T25 | 4万库验证、代表样本长跑、可追溯本地交付包 | AC23-AC25通过；未达性能目标明确记录，不以打包代替验收 |

执行顺序：M0→A→B→C→D。A是首个小范围可测版本，完整稳定性承诺到D验收后再给。每批先做独立假数据回归，再真实页面核对；需要用户正在采集的数据时不打断当前任务。

不按未经验证的工时给固定上线日期。进度按任务完成数和出批标准汇报；慢网页和Electron升级耗时单独记录，不掩盖成“基本完成”。

按工作包逐步提取实际需要测试的模块，不同时大改整个renderer。新模块需随check和打包清单更新，不能出现开发目录可用而App缺文件。

## 5. 数据改动与兼容

- 增量迁移引入schema版本；先备份，迁移可重复执行，错误中止但不清库。
- 增加采集事件唯一ID、字段/模块状态、来源时间、最近成功增强时间，区分计数与尝试次数。
- 任务与待写结果都必须持久化。待写队列独立于后台服务可用性，不能要求失效的3188服务先成功才能缓存数据。
- 历史原始证据保留。去除重复原文只在备份与一致性检查完成后进行；新写入立即避免重复存储。
- 已有空值/0/MCN错误不能直接批量猜测修复；优先从有口径证据的原始快照重解析，不确定的进入重刷清单。
- 现存2位无ID记录进入待核对；找到稳定身份后才能关联历史，不删除、不伪造ID。
