# 代码复核问题清单

日期：2026-09-13。代码版本：desktop 0.2.3-demo / data-console 0.2.0。

这是审查结果，不是修复完成记录。所有问题当前均为 Open；归属为 rednote 开发。P1 为数据准确性、核心可靠性或云端上线阻断；P2 为重要体验、性能和维护问题。未发现本机已经对公网开放的证据。

## P1：采集身份与指标口径

### R01 搜索未准确匹配时采集无关博主

- 位置：[renderer.js](../../desktop/src/renderer.js#L2631)。
- `findBestSearchRow` 按精确、包含、第一行依次兜底；搜索超时后只要还有列表，也可能判为搜索完成。
- 复现：搜索 Wanted，列表仅有 Unrelated，返回 Unrelated。昵称上传和相似种子都使用该函数。有 ID 只能证明拿到了某个博主，不能证明是用户要找的博主。
- 建议：搜索响应与当前关键词绑定；只接受明确匹配。无结果、多个同名、昵称变更分别记录到待核对清单；已入库博主使用稳定 ID 校验。

### R02 新 ID 未命中时仍按昵称与小红书号合并

- 位置：[db.js](../../data-console/src/db.js#L718)。
- 输入带有效新 ID，但主表没找到时，仍退回 `red_id + nickname`，继而修改旧行的 blogger_id。
- 复现：ID A、ID B 同昵称同小红书号，被合为一条，A 的历史挂到 B。
- 建议：双方都有非空 ID 且不同，禁止自动合并。辅助匹配只用于无 ID 的历史候选，经过明确校验后迁移。

### R03 日常、合作、累计和时间窗口存在混用

- 位置：[renderer.js](../../desktop/src/renderer.js#L440)、[解析入口](../../desktop/src/renderer.js#L933)、[接口分类](../../desktop/src/renderer.js#L837)。
- 日常阅读/互动为 0 或空时，会被合作笔记近30日指标替代，字段仍标日常。
- 近30日笔记数缺失时可退回 profile.totalNoteCount；商业笔记数量也有累计兜底。
- 非合作 notes_rate 的30日、90日等响应全部进入同一个 notesRate 槽位，后到响应可能覆盖前一个。
- 复现：日常阅读0被合作阅读321替代；只提供累计999，近30日笔记数变999；非合作30/90日均分类为notesRate。
- 建议：按博主ID、业务类型、时间窗、图文/视频、流量类型、数据日期完整标记；不同口径不得补位。商单占比分母是否包含全部笔记需与真实页面再对照，当前字段名“日常笔记”不足以证明它就是“全部内容”。

### R04 无法获取的数值被处理为零

- 位置：[importer.js](../../data-console/src/importer.js#L134)、[db.js](../../data-console/src/db.js#L1189)。
- `parseNumber` 宽松剥离字符后，`暂无`、`N/A`、`null` 都变0。
- 合作数NULL、笔记数10时，SQL算出NULL，但presentBlogger兜底成0，UI展示0%。
- 建议：按字段类型严格解析，未知保持NULL；明确的数值0保留。比例任一输入未知则未知。

### R05 未读到 MCN 也会被写成“无机构”，产生假变更

- 位置：[renderer.js](../../desktop/src/renderer.js#L925)、[db.js](../../data-console/src/db.js#L753)。
- 页面与接口都无机构信息时默认“无机构”；入库没有要求本次成功、时间更新或前后均明确。
- 复现：已有Example MCN，再写入解析缺失产生的“无机构”，出现退出机构历史。首次读到有MCN也会出现“未记录→MCN”，应区分首次发现与真实变化。
- 建议：未知、确认无机构、确认有机构分三种状态；只比较按数据时间排序的确认结果。保留来源和前后快照。

## P1：入库与运行稳定性

### R06 旧数据或失败快照顶替最新数据

- 位置：[db.js](../../data-console/src/db.js#L603)。
- 每次写入无条件改latest_snapshot_id和last_collected_at，没有比较数据日期或采集质量。
- 复现：9月5万粉的记录再导入1月1万粉，最新显示1万；增强合作数3再录普通采集，最新合作数变NULL。
- 部分重刷沿用旧基础值又更新collected_at，会把旧值展示成刚更新。未知、未尝试和真实零无法区分。
- 建议：历史全留；最新展示按同口径、有效数据时间和质量选择，明确标记旧值来源日期。本次未采到仍留空/缺失状态，不伪装为刷新成功。

### R07 写库失败被吞掉，无持久补传，重试会重复入库

- 位置：[renderer.js](../../desktop/src/renderer.js#L316)、[重刷收尾](../../desktop/src/renderer.js#L3059)、[db.js](../../data-console/src/db.js#L603)。
- 队列只是内存Promise；失败只设置databaseError，不抛出也不持久化重试。
- finishDatabaseBatch与重刷完成提示不检查是否所有记录获得入库确认；每日成功数按采集结果累计，不按数据库确认累计。
- 复现：模拟写入失败，收尾仍返回“已边采边写入”；同批次重放同记录，计数和快照都加两次。
- 建议：本地outbox先落盘、云端事务提交后回执；event_id唯一防重；失败重试、重启恢复、采集数/同步数/失败数分开。

### R08 后台子进程退出后无法自动重启

- 位置：[main.js](../../desktop/src/main.js#L106)。
- 启动只判断对象不存在或killed；自然退出的子进程可能killed=false且exitCode非空。没有exit/error监听清理引用。
- 复现：模拟已退出进程对象，启动函数没有再次spawn而直接超时。与白屏/后台不可用的用户历史反馈吻合，但不能据此认定每次历史白屏都是该原因。
- 另有stdio=ignore，后台日志被丢弃；健康检查只看HTTP成功，未核验服务版本、数据目录。
- 建议：监听退出、重置引用、有上限地重启、持久错误日志；健康检查返回且校验实例、版本和schema版本。

### R09 每日任务缺少可恢复清单、执行锁和有效暂停边界

- 位置：[renderer.js](../../desktop/src/renderer.js#L3110)、[定时器](../../desktop/src/renderer.js#L3358)、[watchdog](../../desktop/src/renderer.js#L226)。
- 调度在Electron页面setInterval里；退出App/关闭窗口/休眠时无法保证执行。候选只保存在本次内存数组，没有持久化待执行项。
- 创建任务前经过多个await后才置运行锁，快速重复提交存在竞争；重启也没有租约、断点或处理中任务回收。
- watchdog以状态文字刷新为“进度”，反复重试仍可能持续刷新文字；强制停止只改标记，不撤销旧异步流程，重新开始后旧流程可能影响新任务。此项为代码路径风险，未做真实长跑复现。
- 建议：服务器任务项+租约+心跳+执行代号；按成功提交/处理位置判断进展；可继续未完成清单，失败独立重试。Mac离线显示等待采集设备。

### R10 公网后台没有账号鉴权和权限隔离

- 位置：[server.js](../../data-console/src/server.js#L60)、[用户参数](../../data-console/src/server.js#L109)。
- 当前员工切换只是指定userId，users没有密码/会话机制，服务端信任用户提交的userId。授权管理的环境开关也不是鉴权。
- 内存库临时HTTP服务复现：不带登录凭证DELETE博主返回200且删除成功。当前默认仅127.0.0.1，本次未将其暴露公网。
- 建议：后台员工登录、服务器计算身份和workspace、角色权限、设备令牌、导出/删除审计。客户授权与员工权限分开。数据表增加workspace隔离。

## P2：规模、查询与交付细节

### R11 筛选导出截断在200条

- 位置：[server.js](../../data-console/src/server.js#L88)、[分页限制](../../data-console/src/db.js#L896)。
- 导出传pageSize=20000但共用列表方法最大200；复现205位只导出200位，无截断提示。
- 建议：独立导出查询，固定本次筛选视图，流式/异步导出并核对总数；不要只把上限调到4万。

### R12 原始数据重复保存、随列表传输并进入CSV

- 位置：[importer.js](../../data-console/src/importer.js#L179)、[db.js](../../data-console/src/db.js#L806)、[exporter.js](../../data-console/src/exporter.js#L26)、[App.jsx](../../data-console/src/ui/App.jsx#L131)。
- raw_json内再次保存raw_api_json，独立raw_api_json列也存一份。列表与每日候选共用latestSelect，全部带出。详情查出所有历史原文，但页面历史仅显示8条。
- 本机实测：50位列表序列化6,039,519 bytes；112位候选13,755,952 bytes。不是4万规模压测，但已能证明请求过重。
- 原始快照字段也被“其他采集数据”自动展示/导出。普通无原始响应的快照保存字符串`{}`，Boolean判断会误显示已保存。
- 建议：列表白名单投影，候选只发身份信息，历史游标分页；原文独立存一次、单独诊断查看，业务CSV用字段白名单。

### R13 更新清单和历史没有完整浏览入口

- 位置：[App.jsx](../../data-console/src/ui/App.jsx#L828)、[db.js](../../data-console/src/db.js#L1086)。
- 失败仅渲染8位，本次明细仅渲染24位；接口失败上限200/明细默认120，无分页。批次只列最新200，详情历史只显示最新8条。
- 本机第二次任务记录32位失败/缺失，因此现有UI无法直接看到全部失败者。
- 建议：完整分页清单、按状态筛选、失败名单导出、仅重试失败、查看历史运行。

### R14 中文子串搜索和标签更新不符合直觉

- 位置：[db.js](../../data-console/src/db.js#L794)、[关键词搜索](../../data-console/src/db.js#L828)。
- FTS unicode61前缀检索：复现“开局”能搜到“开局一口锅锅”，“一口锅”搜不到。
- replaceCollectedTags实际上只插入不删除；刷新后旧采集标签仍匹配，主表标签与筛选可能不一致。
- 建议：中文子串/短词明确测试，最新采集标签按类型替换，人工标签独立保留，历史标签由快照承担。

### R15 快速切换详情可能显示上一位，保存失败无反馈

- 位置：[App.jsx](../../data-console/src/ui/App.jsx#L193)、[详情](../../data-console/src/ui/App.jsx#L265)、[备注](../../data-console/src/ui/App.jsx#L393)。
- 列表和详情请求没有取消或序号校验，旧请求慢返回可以覆盖当前选择。备注/状态保存未普遍检查response.ok。
- 建议：请求取消/选择ID校验，失败保留输入并反馈；多人修改用版本号冲突提示。此项为代码确认风险，未做网络节流UI复现。

### R16 页面加载判定与原始采集仍不完整

- 位置：[renderer.js](../../desktop/src/renderer.js#L857)、[质量门槛](../../desktop/src/renderer.js#L1109)、[合作切换](../../desktop/src/renderer.js#L1164)。
- 403等失败响应也进入缓存；部分门槛只要求对象存在。切换30/90日后看到对应标题就读文本，未绑定本次请求结束和具体指标版本，仍有读旧数据的风险。
- notes_detail等只保留最后一份响应，且品牌/标题/相似数据存在20/10条限额；不能据此宣称采全所有分页、所有筛选维度。
- 建议：每个模块记录请求参数、成功响应、加载完成和数据日期；明确“此次页面实际返回的数据”与“平台全部历史数据”的范围。

### R17 时间、删除与历史兼容

- 时间混用本地无时区字符串、UTC ISO和SQLite CURRENT_TIMESTAMP，再按字符串排序；迁移时需按写入来源统一时区，不能仅凭字符串推断。
- 博主删除级联删除快照/备注，采集可以再创建同一ID；上云后需回收站/删除标记阻止迟到补传复活记录。
- 本机114位中仍有2位历史记录无博主ID；新导入校验未修复历史数据。迁移进入待核对区，禁止杜撰ID或悄悄丢弃。
- 位置：[db.js](../../data-console/src/db.js#L985)、[时间规划](../../data-console/src/db.js#L1012)。

### R18 实际增强流程与旧说明不一致

- 位置：[renderer.js](../../desktop/src/renderer.js#L3497)、[增强开始](../../desktop/src/renderer.js#L2937)。
- 当前开始时传给列表脚本enhancedMode:false；先扫完全部列表页，再runDetailEnhancement按全量记录逐个详情，最后空值自检。不是旧文档“每页详情做完再翻页”。
- 建议：先统一说明与状态阶段，后续用持久任务节点选择是否恢复每页串行流程；避免用户把详情和补采误认成重复翻页。

### R19 发布与工程保障仍不足

- Electron依赖31.7.7系列较旧；官方支持最近三个稳定主版本，正式交付前应升级到受支持线并回归内置浏览器。[Electron支持策略](https://www.electronjs.org/docs/latest/tutorial/electron-timelines)
- main进程未统一验证IPC发送来源；两个webview允许弹窗，缺少集中导航/权限白名单。远程后台集成前按来源划分本地能力。[Electron安全建议](https://www.electronjs.org/docs/latest/tutorial/security)
- 打包为临时签名，未配置Developer ID公证；源码目录不在Git仓库，老App很多，README版本已落后。
- 基线只有14项数据库测试+2项记录工具测试，缺少采集状态机/HTTP权限/真网页慢加载与断网长跑。该清单不是对已受攻击或历史所有故障的推断。
- 建议：单独安排版本升级、Git和发布清单、日志与备份恢复、关键回归，不与首次云端切换混成一次无边界重构。
